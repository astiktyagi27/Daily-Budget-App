## 1. Approach
Create the repository first, then the app inside it, so that line-ending rules and ignore rules are in force before any generated file exists:

1. **Git first.** `git init` at the project root (`daily-budget-app/`), add a root `.gitignore` and a `.gitattributes` (LF for text files, CRLF only for Windows scripts, binaries marked binary). No commits.
2. **Generate a minimal Android-only app** with an explicit package name and org, using the `--empty` template so there is no counter sample to delete:
   ```powershell
   $env:Path += ';C:\src\flutter\bin'
   Set-Location "C:\Users\mayan\Documents\Idea bank\daily-budget-app"
   flutter create --empty --platforms android --org com.dailybudget --project-name daily_budget --description "Daily Budget App: a daily spending budget from bank SMS." app
   ```
   `--platforms android` means no `ios/`, `web/`, `windows/`, `linux/`, `macos/` folders (AC-1; iOS is out of scope per the feature doc and D-001). `--project-name daily_budget` gives a valid Dart package name that does not depend on the folder path with the space.
3. **Set the Android application ID** to the placeholder `com.dailybudget.app` (the template would give `com.dailybudget.daily_budget`): change `namespace` and `applicationId` in `android/app/build.gradle.kts` and move `MainActivity.kt` to the matching Kotlin package folder. This is a **placeholder**, to be finalised in Phase 7 together with the app name, before the first Play upload (an application ID cannot change after release).
4. **Strict lints:** replace `flutter_lints` with `very_good_analysis` (see §4).
5. **Layer folders** `core/`, `data/`, `domain/`, `features/` under `lib/`, each with a short `README.md` stating the layer's rules (what may live there, what it may import). This lets git track the folders (AC-2) without adding Dart dead code or empty placeholder classes (STANDARDS §5). Real code goes where it belongs: the placeholder screen in `features/placeholder/`.
6. **Placeholder app:** `main.dart` only calls `runApp`; `app.dart` holds the `MaterialApp`; the screen shows exactly the two texts from feature doc §5. No AppBar, no buttons, no theme work (default Material 3 theme from `MaterialApp`).
7. **Tests named by TC ID:** a widget test for the placeholder, plus a small permanent "architecture guard" test that fails if any file in `lib/domain/` imports `package:flutter` or `dart:ui` (AC-3 is then checked automatically on every run, for every future phase).
8. **One-command check:** `tool/check.ps1` at the project root runs `flutter pub get`, the format check, `flutter analyze` and `flutter test` from `app/`, stops on the first failure, and exits non-zero if anything fails.
9. **Record decisions** (versions, lint set, library choices, application ID, Android-only) in `docs/DECISIONS.md`.

**Packages added now vs. only recorded.** Phase 0 adds to `pubspec.yaml` **only what Phase 0 code uses**: the lint set (`very_good_analysis`). State management, database and logger are **chosen and recorded** now with exact versions, marked "added in Phase N", and added by the first feature that uses them. Why: STANDARDS §1 (no speculative code), §5 (no unused code); unused dependencies would also make `flutter pub get` pull native SQLite build hooks into a placeholder app, and their versions would go stale before Phase 1–2 anyway (AC-11 version-drift edge case). The feature that adds each package re-checks pub.dev and updates the `DECISIONS.md` row if a newer stable version exists.

**Alternatives rejected**
- *Default template + delete counter app/test* — more to delete and risk of leftovers; `--empty` gives a minimal `main.dart`.
- *Git repo inside `app/`* — rejected by the feature doc (one repo at the root covering docs, plans, tests and app).
- *Empty `.gitkeep` files or empty Dart files in layer folders* — `.gitkeep` carries no information; empty Dart files are dead code. A short `README.md` per layer documents the architecture contract instead.
- *Adding Riverpod now with a bare `ProviderScope`* — no provider exists yet, so it would be unused scaffolding; it comes in Phase 1 with the first real provider.

## 7. Edge cases & risks
| Case / risk | How it is handled |
|---|---|
| Windows host, PowerShell vs Git Bash | `check.ps1` is PowerShell 5.1-compatible (no `&&`, no `??`); documented Git Bash call `powershell -ExecutionPolicy Bypass -File tool/check.ps1`. Plain commands (`flutter …`, `dart format …`, `git …`) are identical in both shells. No hard-coded `/` root paths. |
| Space in project path (`Idea bank`) | Every documented command quotes paths; `check.ps1` uses `$PSScriptRoot` + `Join-Path` and `Push-Location -LiteralPath`. If Gradle fails because of the space (AC-13), log a bug with the exact error; moving the project is an Owner decision. |
| Flutter not on PATH | `check.ps1` falls back to `C:\src\flutter\bin\flutter.bat` (and `dart.bat`) if `flutter` is not found, and prints which one it used. Task notes record how commands were run. |
| Android SDK missing | `flutter create`, `pub get`, `analyze`, `test` do not need it (AC-12). `flutter doctor` Android errors are expected. AC-13 / T-008 is **Blocked**, not failed. |
| Windows Developer Mode / symlinks | Phase 0 adds **no plugin packages** (only a dev lint package), so the "requires symlink support" warning should not appear. If it does, note it for the Owner (README §13 step 4); it does not block AC-4–AC-7. |
| Generated sample code | `--empty` template: no counter app. Any generated `test/widget_test.dart` is deleted (AC-6); `app/README.md` deleted. |
| Strict lints vs generated files | No `exclude:` entries. Only rule override: `public_member_api_docs: false` — this rule is meant for published packages; for an app it forces doc comments on every public widget/class and conflicts with STANDARDS §5 "clear names over comments". Flagged for the Project Manager in §9. If any generated platform file under `android/` produces analyzer issues (it should not — Kotlin/Gradle are not analysed), it is fixed, not excluded. |
| Empty layer folders | One `README.md` per layer (documents the rule, no dead Dart code). |
| Dart package name | Set explicitly with `--project-name daily_budget`. |
| Line endings (CRLF/LF) | `.gitattributes` created **before** `flutter create`, so files are normalised to LF in the repo and checked out as LF regardless of the user's `core.autocrlf`; `dart format` stays clean after a fresh checkout (TC-001-38, TC-001-39). `.ps1/.bat/.cmd` keep CRLF for Windows; `gradlew` stays LF, `gradlew.bat` CRLF. |
| Long Windows paths (260 chars) | Not hit by analyze/test. If AC-13 fails on Gradle path length, log a bug with the exact error; the fix (enable long paths or move the project) is an Owner decision because it changes system settings. |
