## 0. How to run these cases (shared by F-002 … F-005)

The Phase 1 test files F-003, F-004 and F-005 use the definitions in this section. They are not repeated there.

**Environment:** as F-001 §0 (Windows 11, PowerShell 5.1, Flutter 3.47.9 / Dart 3.13.7 at `C:\src\flutter`, emulator `emulator-5554` = AVD `Medium_Phone_API_37.0`, Android 17 / API 37). Setup **S1** from F-001 §0 before every run. Commands run from `app/` unless stated.

**Definitions**

| Name | Meaning |
|---|---|
| **T5** | The theme matrix "all four themes" (F-002 §3): **Light**, **Dark**, **Dim**, **Auto + system light**, **Auto + system dark**. In widget tests the system setting is `tester.platformDispatcher.platformBrightnessTestValue`; reset in `addTearDown`. |
| **Small** | 360 × 640 dp: `tester.view.physicalSize = const Size(1080, 1920)`, `devicePixelRatio = 3`; reset with `tester.view.reset` in `addTearDown`. |
| **X1 / X2** | Text scale 1.0 / 2.0: `tester.platformDispatcher.textScaleFactorTestValue`; cleared in `addTearDown`. |
| **P1 screens** | "Every Phase 1 screen" (F-002 §3), as test states: Home, Dashboard, Transactions, Settings (top **and** scrolled to the end), theme picker open, (i) explanation open (Theme (i), the longest Phase 1 body), each of the four tabs with its first-time hint visible, tour slides 1–4, SMS explainer, notifications explainer, disclaimer. **18** states (`P1Screen` in `test/support/p1_screens.dart`). The helper that drives the app into each state lives in `test/support/` and is shared by every sweep test. |
| **FakeStore** | An in-memory fake of the shared preferences store (F-002/F-004/F-005 use one store). Modes: `empty` (fresh install) · `seeded({...})` · `readFails` (every read throws) · `writeFails` (every write throws; reads return the last good value) · raw corrupt values (wrong type, unknown string). It exposes its backing map so tests can assert what was saved. Files (plan F-002, Gate 3 E9): `InMemoryPreferencesStore` (`lib/data/preferences/`, modes `empty` / `seeded` / raw corrupt values) and `test/helpers/failing_preferences_store.dart` (`readFails` / `writeFails`, throws on purpose; shared backing map for Restart (sim)). |
| **Restart (sim)** | Simulated restart in a widget test: `pumpWidget(const SizedBox())` to dispose the whole tree (and its `ProviderScope`/container), then pump a brand-new app on a **new** store object that shares only the old backing map. Nothing in memory survives except the map. |
| **Restart (real)** | On the emulator: `adb shell am force-stop com.dailybudget.app`, then `adb shell am start -n com.dailybudget.app/.MainActivity`. "Swipe away" = recents → swipe the app card. |
| **Fresh (real)** | `adb shell pm clear com.dailybudget.app` (cleared app data = fresh install). |
| **No-error UI** | None of these are found: `ErrorWidget`, `AlertDialog`, `SnackBar`, `MaterialBanner`, and `tester.takeException()` is `null`. |
| **Overflow check** | `tester.takeException()` is `null`; no `FlutterError` whose text contains `overflowed` was reported (capture `FlutterError.onError` for the test); and no `RenderParagraph` in the tree has `didExceedMaxLines == true` (text cut off with "…" or clipped by `maxLines`). |
| **[P]** | Needs the **real preferences plugin on the emulator** (or in an integration test). Windows Developer Mode is **not** needed for this Android-only app (D-029). A case is recorded **Blocked** (never Fail) only for an **environment** failure outside the app, e.g. a missing SDK/NDK or no emulator; record the exact error. If such a failure stops every Android build, every Manual emulator case in F-002 … F-005 is Blocked for the same reason and recorded the same way. Widget tests use FakeStore and do not need the plugin at runtime. |

**Conventions**
- Every automated test name starts with its TC ID and a space (`tool/check.ps1` enforces `TC-NNN-NN `). A test that loops over T5 or over P1 screens is **one** test per TC ID; it names the failing theme/screen in its `reason:`.
- Expected copy is written in the tests as **string literals** copied from the feature doc §5, never read from the app's own constants (house rule from F-001: comparing against the app's constants would let a typo pass). The same applies to colour hex values from `docs/design/design-system.md` §2.
- Accessibility guidelines used by the sweep tests: `meetsGuideline(textContrastGuideline)`, `meetsGuideline(androidTapTargetGuideline)`, `meetsGuideline(labeledTapTargetGuideline)` (each with `tester.ensureSemantics()`, disposed at the end).
- Proposed test files (the Developer's plan may rename them; TC IDs and test names are fixed): `test/core/theme/theme_tokens_test.dart`, `test/core/theme/theme_choice_test.dart`, `test/core/theme/fonts_test.dart`, `test/core/widgets/base_components_test.dart`, `test/features/settings/theme_picker_test.dart`, `test/architecture/tokens_only_test.dart`, `test/features/screens/p1_screen_sweeps_test.dart` (the T-138 sweeps), `integration_test/preferences_persistence_test.dart`.
