## 0. How to run these cases

**Environment and shared definitions:** as F-002 §0 (**T5**, **Small**, **X1/X2**, **Overflow check**, **No-error UI**, **Restart (real)**), F-007 §0 (**[MEM]**, **[FILE]**, **[EMU]**, **[FAKE]**) and F-008 §0 (**Today(d)**, **Fake repos**; the real F-006 engine is used, not faked; **Sheets and finders**: every "dialog" here is a decision sheet found by text, and on-screen money text is compared through `findCopy`, which ignores U+00A0/U+2060). **Scheduling (D-033):** screen code and widget tests may run before Phase 1 is approved; wiring the Transactions tab into the shell and every **[EMU]** case wait for approval.

**Additional definitions**

| Name | Meaning |
|---|---|
| **M-E2** | Confirmed month E2 (F-006 §0): salary day 5, 5 Nov–4 Dec 2026, 83,000 paise a day |
| **Today line** | The line at the top of the Transactions tab. Expected text is the full literal, e.g. `Today: budget ₹830 · spent ₹250 · ₹580 left today`. A test also checks the result part's colour token (`saved` / `overspent` / neutral) **and** that the words are present |
| **Weekdays (2026)** | Thu 5 Nov, Fri 6 Nov, Sat 7 Nov, Sun 8 Nov, Mon 9 Nov, Tue 10 Nov, Fri 20 Nov |
| **P2 transaction states** | For sweeps: no month; month without spends; list with 6 spends over 3 days; list with 50 spends on one day; Today line in each result (left / on budget / overspent / shortfall month); new month not set up; Add spend (empty, with errors, note at 95/100 with counter); Edit spend; Delete dialog; Discard dialog (add and edit); cover-taken-back note; load error state. 15 states |

**Test files** (plan F-009 §2; the file names in the "Automated test" column are the Tester's proposal, the plan's names win): `test/features/transactions/*_test.dart` (tab, today line view, spend editor — the plan's Add/Edit is a full screen `spend_editor_screen.dart`, delete dialog, cover note), `test/domain/budget/today_line_test.dart` (TC-009-10 and the pure part of the Today-line cases), `spend_draft_test.dart`, `spend_groups_test.dart` (grouping/order behind TC-009-13/-36 — unit tests may carry the same TC IDs), `test/a11y/phase2_screen_sweep_test.dart` (TC-009-20, shared with F-008), `integration_test/transactions_500_test.dart` (TC-009-19) and `integration_test/manual_transactions_flow_test.dart` (TC-009-45; may be merged into the plan's integration file).
