### 2.3 Notes for the Project Manager / Product Manager / Designer
**Notes 1–4 resolved at Gate 2** (design review §2 rows 1, 2, 4, 5): the (i) explanation is a help sheet with title, scrolling body and a pinned **Got it**; the screen-reader label is `More about <label>`; the hint card has `Tip`, × and Got it; descriptions always wrap and are never truncated. The hint copy is the final F-004 §5 text. Original notes, kept for history:
1. **(i) form:** design system §7.11b = a tap-to-show **tooltip bubble** (max 3 lines, closes on tap anywhere / scroll / **after 6 s**, "Learn more" opens a sheet). F-004 = an explanation (sheet or popup) with title, body and a **Got it** button. A bubble with no Got it cannot pass AC-2/AC-3, and the 6 s auto-close is not in F-004.
2. **(i) screen-reader label:** design system `About <label>`; F-004 AC-4 `More about <label>`. TC-004-05 uses `More about <label>`.
3. **Hint close button:** design system hint card has only `Got it`; F-004 requires `Got it` **and** ×. TC-004-09/-10 expect both.
4. **Description length:** design system §7.11a "max 2 lines"; F-004 §4 "wraps, never truncated". TC-004-01 expects wrapping with no "…".
Also the design system's example hint copy ("Tap any day on the calendar…") differs from F-004 §5; tests use F-004 §5.

Other notes:
- **AC-3 "screen-reader focus returns to the (i)"** cannot be observed directly in a widget test. TC-004-03 checks keyboard focus as a proxy; TalkBack is checked by hand (TC-004-04), which may be Blocked if the AVD has no TalkBack.
- **AC-5** is automated by matching every tappable semantics node to table 1.2 (TC-004-06). It is only as complete as table 1.2, so whoever changes a §5 table must update 1.2 too.
- **AC-6** "a check agreed in the plan": TC-004-08 proposes the automated help-copy guard. The plan should confirm the help-copy file path.
- ~~**Back with a hint visible**~~ *Resolved at Gate 2:* Back ignores the hint (not dismissed, not seen); see TC-003-21 (c).
