## 0. How to run these cases

**Environment and shared definitions:** as F-013 §0 (which holds the Phase 3 fixtures **A, B, S, F, M-full, M20, O1, N** with their exact paise) plus F-002 §0 (**T5**, **Small**, **X1/X2**, **Overflow check**, **No-error UI**), F-007 §0 (**[MEM]**, **[EMU]**, **[FAKE]**), F-008 §0 (**Today(d)**, **Fake repos**, **Sheets and finders**, `findCopy`) and F-009 §0 (**M-E2**). **Scheduling (D-033):** the view-model code and screen widget tests may run before Phase 2 is approved if F-006 and F-007 exist (the period history with times is F-007 AC-16, per-period results F-006 AC-21); entry points on Home, Dashboard and Day details wait for F-010, F-013 and F-012. Every **[EMU]** case waits for approval.

**Copy and numbers.** Expected strings are literals of F-014 §5 / `month-statement.md` §13. Money on screen is whole rupees rounded toward zero (D-038, D-046, D-053); the working line always uses whole rupees. Paise literals are in F-013 §0 for the fixtures; the engine is **real** (F-006), only the repositories are fake. Refunds are written `−₹500` as in the design (the AC-11 text `Refunds ₹500` is flagged in §2.3 note 2).
