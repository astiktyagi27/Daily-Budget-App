## 0. How to run these cases

**Environment and shared definitions:** as F-002 §0 (**T5**, **Small**, **X1/X2**, **Overflow check**, **No-error UI**, **Restart (real)**, **Fresh (real)**) and F-007 §0 (**[MEM]**, **[FILE]**, **[EMU]**, **[FAKE]**). **Scheduling (D-033):** the screen and its widget tests can be built and run before Phase 1 is approved; wiring into Home/the shell, and every **[EMU]** case, run only after approval.

**Additional definitions**

| Name | Meaning |
|---|---|
| **Today(d)** | The fixed "today" given to the app through the plan's injectable clock/provider. Widget tests never use the real clock |
| **Fake repos** | In-memory fakes of the months and transactions repositories (F-007 interfaces) with modes `ok` · `writeFails` · `readFails`; they count writes and keep the stored records for assertions. The **real F-006 engine** is used (not faked), so preview numbers are the engine's |
| **E2 entry** | Salary day 5; salary `40000`; switch off; Rent `10000`, EMI `5000`, Subscriptions `100` |
| **P2 setup states** | For sweeps: first setup (empty); first setup with E2 entry; 10 fixed costs + a salary error showing; target switch on; shortfall card; shortfall dialog; equal-case card; mid-month setup; pre-filled new month; edit this month (with the From-today line); discard dialog; Home: no month, This month card, new-month notice, shortfall line; storage error screen (F-007). 18 states |
| **Type** | `enterText` into a field found by its label (`find.widgetWithText(TextField, 'Monthly salary')` or the plan's keys) |

**Sheets and finders (Gate 2):** there are **no Material dialogs** in Phase 2; every "dialog" in these cases is a design system §7.8 decision sheet (`showBudgetSheet`). Find sheets and their buttons by text and semantics (`find.text`, `find.bySemanticsLabel`), never by `AlertDialog`/`Dialog` type; "back" on a sheet means the safe choice. Money text contains a word joiner (U+2060) after `−` and non-breaking spaces (U+00A0) inside phrases such as `spent ₹250`; compare on-screen text through a shared helper (`findCopy` in `test/support/`) that maps U+00A0 to a space and drops U+2060. Formatter unit tests (TC-008-29) compare the raw output, including U+2060. Semantics labels have no invisible characters and say "minus".

**Copy and numbers:** expected strings are literals from F-008 §5 / §2 (house rule, F-002 §0). Expected stored values are paise literals (F-006). Money on screen is whole rupees rounded down (D-038, AC-19). The rupee sign is `₹`; the minus sign follows the design system (U+2212 `−` unless the design says otherwise; the test uses the design's character).

**Test files** (plan F-008 §2; the file names in the "Automated test" column are the Tester's proposal, the plan's names win): `test/features/month_setup/*_test.dart` (screen, preview, shortfall, edit), `test/features/home/home_month_states_test.dart` (Home states; written below as `home_month_card_test.dart`), `test/core/format/money_format_test.dart` (TC-008-29), `test/architecture/money_format_only_test.dart` (TC-008-30), `test/domain/budget/amount_input_test.dart` and `setup_draft_test.dart` (pure parsing/draft rules behind TC-008-05/-06/-31/-32/-34/-43 — the Developer may add unit tests there with the same TC IDs), `test/copy/copy_tables_test.dart` (copy literals), `test/a11y/phase2_screen_sweep_test.dart` (TC-008-24, shared with F-009), `integration_test/month_setup_flow_test.dart` (TC-008-18, -54). Today is injected through the plan's `clockProvider`/`todayProvider`.
