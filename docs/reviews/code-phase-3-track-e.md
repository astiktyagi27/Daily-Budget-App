## F-015 Transactions list

**Correct.**
- `transaction_search.dart` (pure Dart, no Flutter import, integer paise): `parseSearchQuery` delegates to `parseAmount` (one amount rule, F-008), spaces or `₹` alone are empty, a number query without a decimal point compares the shown whole rupees (`~/ 100`, D-038) and with a decimal point the exact paise, and also matches notes containing the typed digits (with and without grouping commas). A text query is a case-insensitive substring of the note, `No note` is display text and is not searchable (D-082 (7)). Type, category (OR inside the set, AND with the rest) and dates combine as the doc says. `resolveDates`, `lastMonthOf`, `normalizeDates` implement D-083 (3) (new month not set up: default is the latest stored month, `This month` unavailable). `resultsSummary` gives the gross of matching spends, null when none, refunds apart (D-082 (8)). `groupEntries` reuses F-009's `groupSpendsByDay`, so order, headings and net totals are F-009's (D-048 (8)).
- Day totals under a filter are the shown entries only and say `shown` (AC-10). The list is a lazy sliver (`SliverList.builder`), the filter state is a non-auto-disposed notifier (AC-15: survives a tab switch, never stored), and the search sets `state` 250 ms after the last keystroke, cancelled on dispose, on clear and on `Clear all`. A stream that has not answered keeps the old rows on screen (`_shown`); an error has its own retry.
- Layers: the screens call no repository except through providers and `category_change_flow.dart`; no money arithmetic or money threshold in any widget (formatting only, the results line takes the pure summary); colours and spacing are tokens; the one literal duration is the named `searchDebounce` / `undoWindow`.

**Write path (T-420), the approved F-007 interface change (D-082 (2), D-084 (6)).**
- `SpendFields` gained `category` and `direction`; `add` lost its `direction` parameter; `update` now also writes `direction` and `category`; new `updateCategory(id, category, now)`; `StoredSpend.noted`. **Additive, no schema change:** the `category` column already existed (`app_database.dart` line 126), `direction` already existed, no migration, no trigger touched, no new package. The append-only triggers cover periods and fixed costs, not `transactions`, so a direction write is allowed (D-084 (3)).
- `updateCategory` writes only `category` and `edited_at` and does **not** call `reconcileStoredCovers`: a category is not money (AC-13), proved by a unit test that covers stay untouched and engine results are deep-equal. It refuses money in (`ArgumentError`), works on any month (AC-14), and an unknown id fails. `_validate` also refuses a refund that carries a category, so a refund never stores one even if a caller forgets.
- Existing F-009 callers were edited mechanically (12 uses); the whole suite must be green (conditional approval above). `drift_mappers.dart` reads the category with `SpendCategory.fromKey`.

## F-016 Money back

**Correct.**
- `SpendDraft.moneyBack` drives `toFields`: direction `moneyIn`, category dropped in the same write (AC-2, AC-7, D-084 (3)), limits identical to a spend (amount, date, mid-month and late start). `isChangedFrom` includes the switch, so turning it on or off in Edit enables `Save changes` and arms the discard guard; the category is ignored in the signature while the switch is on (a refund has none), so the picked category waits in the draft and returns when the switch is turned off.
- No engine, rounding or money rule was touched: refunds, covers and the pot move only through the existing `add` / `update` / `delete` and `reconcileStoredCovers`. `money_back_effects_test.dart` proves it on a real in-memory Drift: AC-5 figures, AC-9 covered day and delete afterwards (the cut cover does not come back), AC-10 pot shrink with the `reductions` list (seeds P1 and P1b; the Developer confirmed them against `phase3_fixtures.dart`, which closes T-444's seed half), shortfall month, ₹0.40, conversion writing `direction`. **No effect failed: no engine bug.**
- Editor UI: the switch row (`MoneyBackSwitch`) is one screen-reader node `Money back / refund, switch, off` plus its description, the whole row toggles, it stacks the switch under the texts above 1.3x, the visual `Switch` is excluded from semantics so there is no double stop, focus ring included. Title, amount label, `+₹` prefix, note description, Save hint, delete and discard sheets follow the mode; the Category row collapses (`AnimatedSize`, `motion.emphasis`, instant with Remove animations); the outcome is named by what the entry is after the write (`Spend updated` after turning the switch off, D-084 (4)); a failed write keeps the input and the dock error says `Couldn't save`; `_saving` and the editor's busy flag give one record per double tap.
